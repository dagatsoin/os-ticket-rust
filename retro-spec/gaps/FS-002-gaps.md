## Three most significant gaps
1. **Logout link-token guard is a no-op** (gap #1): the missing `exit` after the redirect means logout always succeeds regardless of the `auth` token — the documented forced-logout-CSRF defence does not exist.
2. **Password-reset time window never enforced** (gap #2): the dead boolean condition means reset tokens are time-unbounded; they live until explicitly cancelled, contradicting the "30-minute window" the spec promised.
3. **DB-backed session handler bypassed on installed systems** (gap #3): the entire DB-session feature set (per-row expiry/owner/IP, online-users, custom cookie scoping) is only wired up in the uninstalled state; a normal install falls back to default PHP sessions.
