## Summary

- **Gaps found / fixed: 9** — MISSING ×3, INCORRECT ×3, IMPRECISE ×3.
- **Most significant:**
  1. (#1) BS-011.4 was materially wrong: it claimed the over-limit admin alert is unconditional, but the source gates both the user e-mail and the admin alert behind `overlimit_notice_active` plus an `(autorespond && non-staff)` flag — only the warning log is unconditional.
  2. (#4) Attachment display-vs-processing gate asymmetry — the handler accepts attachments on a login-only configuration even when the form never showed the input (latent trust gap, now BS-011.12).
  3. (#5) A prior validation error (notably CAPTCHA failure) silently skips attachment validation and discards uploads, since file inputs can't be repopulated (now EC-011.10 + KL-011.6).
- **New rule counts for FS-011:** +4 BS (BS-011.9–BS-011.12), +2 EC (EC-011.10, EC-011.11), +2 KL (KL-011.6, KL-011.7). No new FRs (all gaps folded into existing FS-011.1/.3/.7/.9/.12/.13 acceptance criteria). No existing IDs renumbered.
